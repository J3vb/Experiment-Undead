# Import an asset into Godot

## Import

```bash
./godot --headless --path . --import
```

This writes `<file>.import` next to the asset. Commit the asset **and** its
`.import`. Never commit `.godot/`.

## Settings that matter (`<file>.glb.import`, `[params]`)

| Setting | Value | Why |
|---|---|---|
| `meshes/light_baking` | **2** for kit and static props (walls, floors, machines that never move) | Static lightmaps; needs UV2, Godot makes it on import |
| `meshes/light_baking` | **3** for anything that moves (zombies, guns, doors, pickups) | Dynamic: lit by real-time lights and LightmapGI probes |
| `meshes/lightmap_texel_size` | 0.2 for kit | Matches the rest of the kit |
| `meshes/generate_lods` | true | Godot builds LODs |

Copy the `.import` of a similar asset (`assets/models/kit/wall_panel.glb.import`
for kit, `assets/models/zombies/shambler.glb.import` for actors), then change
only the paths and keep Godot's own `uid` line from your import run.

Kit materials: map the glb material names to the shared materials in
`levels/materials/` under `_subresources` (see `wall_panel.glb.import`), so
every wall uses the same `panel_paint.tres`. Reuse those materials before
adding new ones.

Light nodes are separate from mesh import. `Light3D.light_bake_mode`:
0 Disabled (cheat lights like `ZombieRim`, `ViewFill`), 1 Static (bake only;
skips lightmapped surfaces at run time), 2 Dynamic (fixtures).

## What not to commit

- An editor-touched `project.godot`. Revert it unless your task needs a change
  there (one `[autoload]` line at the end, for example).
- `.tres` / `.tscn` files the editor re-saved without a real change. Editor
  re-saves add machine-local `uid`s that break CI. Commit only files you meant
  to change; check `git diff --stat` before committing.
- The `*.unwrap_cache` next to a model is fine to commit when Godot makes it.

## Tests

`tests/content/test_generated_models.gd` has one test per model: it loads the
model and checks size, axes and the parts code needs by name. When you add a
model, add a test function like `test_shambler_is_upright_and_reaching` that:

- checks every node code finds by name (`Magazine`, `Muzzle`, `Bolt`, `Head`,
  `Belly`),
- checks the size and which way it faces,
- for a gun, adds it to the triangle budget and light baking checks
  (`test_rebuilt_guns_keep_rifle_triangle_budget_...`,
  `test_rebuilt_guns_use_dynamic_light_baking`).

Run:

```bash
./godot --headless --path . -s addons/gut/gut_cmdln.gd -gselect=test_generated_models.gd
```

## Gotchas

- `godot -s script.gd` does **not** load autoloads. A tool script that needs
  `Log`, `Events` or `Content` must run from a small `.tscn` instead.
- A level with LightmapGI needs a re-bake in the editor on a GPU after any
  geometry or light change (`docs/design/look-rules.md`, Light rules). A cloud
  agent cannot bake: write the steps in the PR so someone with a GPU can.
- Sounds: generated by `tools/generate_sfx.py` / `generate_music.py`; same
  rule, the script is the source.
- Third-party files: one line each in `docs/CREDITS.md` (name, author, link,
  licence). CC0 first, CC-BY with credit. No "non-commercial" or "no AI".
