# Prototype decisions

The prototype follows the architecture doc
(https://claude.ai/artifact/XNJ12WAbMJAy2mRNPd5PCx). This file lists what is
built, what was simplified on purpose, and what is still to do.

## Built and matching the doc

- **Godot 4.7.2, Forward+, Jolt at 60 Hz, physics interpolation on.**
- **Typed GDScript enforced:** `untyped_declaration` and `inferred_declaration` are errors (addons excluded).
- **Folders:** `core/` autoloads, `systems/<feature>/` code + scenes, `content/<type>/` data only.
- **Autoloads:** `Events` (past-tense facts only), `Content` (id = file name, strips `.remap`), `Net` (`is_authority()`, id allocation).
- **Content as Resources:** `WeaponData` + `RecoilData` (per-shot pattern), `EnemyData`, `WaveRules` + `EnemySpawnEntry`, `EconomyRules`. Live state is in `WeaponInstance`; `.tres` files are never mutated (tested).
- **Damage:** `DamageInfo` (amount, attacker, weapon id, type, zone, position, normal, impulse) → `HitZone` (Area3D on layer 4) → `HealthComponent`. Weapon head/limb multipliers from data, per-zone armour on the HitZone.
- **Collision layers 1-8** named as in the doc.
- **Multiplayer rules:**
  1. Player reads `InputFrame`s from a `LocalInput` node, never the keyboard.
  2. Damage, spawns, XP only apply where `Net.is_authority()`.
  3. Logic emits facts; muzzle flash, sound, impacts and hit markers react (weapon `fired`/`traced` signals).
  4. Gameplay in `_physics_process`; `GameSession.tick` counts ticks. Weapon `tick()` runs from the player's physics step; `_process` is visuals only.
  5. All enemies come from `Spawner`, which assigns `net_id`.
  6. Gameplay randomness uses `GameSession.rng` (seedable).
  7. XP goes through `ProgressionService` (one in-memory class for now).
  8. No global player: everything loops the `players` group.
- **Economy:** per-player `Wallet`; `Economy` pays from `EconomyRules` and owns `try_spend()`.
- **Wave director:** intermission → `round_started` → spawning (max alive cap, extra per player) → clearing → `round_ended`.
- **Zombie AI:** enum state machine (Spawning, Entering, Chasing, Attacking, Dead), NavigationAgent3D with avoidance off plus cheap separation, re-path interval by distance (0.25 / 0.5 / 1.5 s), target = nearest living player every 0.5 s.
- **Fire timing:** time accumulator plus a 0.12 s input buffer, semi / burst / auto.
- **Look:** volumetric fog, depth fog, AgX, SSAO, glow, flickering shadowed lamps, moonlight, player flashlight.
- **Look reference (Cold Containment):** `levels/look_reference/halcyon_corridor.tscn` rebuilds the style guide's Halcyon Labs corridor in Godot. Its `WorldEnvironment` points at the shared `levels/looks/halcyon_interior.tres`; interior game scenes must use this file, not a copy. Render it with `tools/look_shot.gd` (command in the file). Differences from the guide's table, on purpose: AgX instead of ACES; ambient energy 0.2 instead of 0.35 (baked bounce now fills the shadows); fog albedo is a light teal-grey because Godot's fog albedo is the scatter colour (the guide's #0A1416 was the web renderer's fog colour). Grain and vignette come from `systems/effects/film_post.tscn` (a CanvasLayer any scene can add). Zombies there are the code-built Shambler, Crawler and Bloater models (static, no game logic), and no light flickers so renders stay comparable. Style-guide light budget: at most 6 shadowed real-time lights in view (tested). Surface detail is procedural and world-space, no texture files: `levels/materials/grime.gdshader` (wall drips, floor-level dirt, ceiling stains; the wall panel's glTF materials are remapped to it in its `.import` file) and `wet_tiles.gdshader` (tiles, grout, mirror puddles for SSR). Fixtures have a dark housing; one unshadowed `ZombieRim` spot behind the zombies shines back toward the player so silhouettes read. Bounce light is baked with LightmapGI (High, 3 bounces, denoiser, texel scale 2; about 2.3 MB in `halcyon_corridor.exr` + `.lmbake`, plain git). Fixtures and the bio-leak glow use bake mode Dynamic: direct light and shadows stay real-time, only their bounce is baked. `ZombieRim` and the camera `ViewFill` are cheat lights with bake mode Disabled. Zombies and the rifle import with light baking Dynamic, so they are not baked and take light from the lightmap probes. The wall panel imports with Static Lightmaps (UV2, `.unwrap_cache` committed so UV2 is the same on every machine). `Block` builds its box at runtime as an internal child, which LightmapGI skips (it ignores unowned nodes), so `Block` hands the box over through `get_bake_meshes()` / `get_bake_mesh_instance()`, the hooks GridMap uses. **Re-bake after any geometry or light change:** Godot 4 has no command-line bake, so open the scene in the editor on a GPU, select `LightmapGI`, press Bake Lightmaps, save, and commit the new `.exr` and `.lmbake`.
- **Halcyon Labs (default map, blockout):** `levels/halcyon_labs/layout.json` holds rooms (rect, floor height, ceiling height), door cuts and ramps as plain data. `tools/blockout_builder.gd` turns it into `blockout.tscn` (command in the file; never hand-edit the output, a test fails if it is stale). Walls are runs of the code-built wall panel with one collision box per run; ceiling lights are the kit scene `levels/kit/ceiling_light.tscn`, two shadowed per room. `map.tscn` holds the gameplay nodes: player spawn, 21 `ZombieSpawnPoint`s (each tagged with its area), dock props, orange doors and green machine placeholders. `Level.open_area()` puts an area's spawn points into the Spawner's group; only the Loading Dock is open at the start. Closed doorways cut the navmesh (tested). Layout and costs follow the maps doc (https://claude.ai/artifact/UxyrXQqFfonMxh3MgFMYWY). The prototype courtyard is removed.
- **Interactables:** `Interactable` (Area3D on the interactable layer, `get_prompt()` + `interact()`); the player ray-casts 2.5 m from the camera each tick into `Player.focus`, presses interact, and the HUD shows the prompt. `Door` (cost, area, needs power; doors to the same area open together; opening frees its blocker and rebakes the navmesh at the end of the frame, one bake for any number of doors; the bake runs on the main thread because threaded bakes never finished on the 2-core CI runner, so a purchase costs one short hitch (move to per-area regions if it shows in profiling)), `PowerSwitch` (`Level.turn_power_on()`, free power doors open themselves), `WallBuy` (gun at its `WeaponData.cost`, ammo for half). All four Halcyon Labs wall guns are real WallBuys; no wall-gun placeholders remain. The map's NavigationMesh is local to scene, so a restarted match never shares a mesh that is still baking.
- **Serums and Med Dispensers:** `SerumData` (`content/serums/`) is a name, a cost and a dictionary of stat multipliers. `Player.get_stat()` multiplies the multipliers of every Serum the player holds; the gun reads `reload_time`, `fire_interval`, `ads_time` and `head_damage` through it, and the player applies `max_health` and `weapon_slots` when a Serum is bought. This is the small first step toward the StatBlock of P5, which replaces it. `MedDispenser` (`systems/interactables/med_dispenser.tscn`) sells one Serum, needs power (its strip lights up when the power comes on), once per run. All eight Serums are real: Ironhide, Quickhands, Overclock, Deadeye, Mule, Stride, Second Wind, Scavenger. Stride doubles `sprint_time` and halves `sprint_out_time` (the gun's sprint-to-fire delay); its "slide 25% further" waits for a slide. Prices are the design doc's base prices, like the doors (the balance sheet's provisional x2.5 is not applied). Provisional: all dispensers need power, no limit on how many Serums a player holds.
- **Reforger:** Tier I only. `Reforger` swaps the gun in hand for `WeaponData.upgraded` (a separate `*_reforged.tres`: damage x2, magazine +50%, reserve x2, checked by a content test) in the same slot with full ammo, for 5000. A gun with no further tier buys a full refill for 2500. Wall-buys treat the Reforged gun as owned and sell its ammo for 4000 (balance sheet, provisional). Instant swap, no waiting animation yet. Tiers II (ammo mods) and III come later.
- **Brenner Trench (third gun, wall-buy 750 in the Loading Dock, the start area, per the maps doc):** pump shotgun, 8 pellets, code-built model `shotgun_brenner.glb` (the wooden pump is the `Bolt` node, so the existing bolt kick racks it, and the left hand rides on it). Pellet damage is the balance sheet's 35 scaled by the same 0.57 the prototype AR uses (34 vs 60), so 20 x 8. Reload is one timed action for the whole tube (2.6 s, 3.6 s empty) instead of shell by shell; per-shell reload comes with real animations. Shared sounds except its own generated `shotgun_fire.wav`.
- **Kestrel SMG (wall-buy 1000 at the existing Halcyon Labs spot):** automatic, 850 rpm, 30 rounds and 180 reserve, 12–35 m falloff, 2.5x headshots; balance-sheet damage 26/17 uses the provisional 0.57 prototype scale (14.82/9.69). Tier I Kestrel Reforged doubles damage and reserve (29.64/19.38, 360 reserve) with a 45-round magazine. Code-built compact model, folding wire stock, straight magazine, iron sights and its own short generated shot; shared dry-fire and reload sounds. Provisional feel: 3.0 hip spread, 0.2 bloom per shot, lighter vertical recoil with more lateral sway, 0.18 s ADS, 2.0/2.6 s reload. Wall ammo costs 500; also in the Specimen Vault pool.
- **Talon DMR (wall-buy 1500 in Generator Hall):** semi-auto marksman rifle, 300 rpm, 15-round box magazine, long braked barrel, fixed stock with cheek riser and a 3x scope. Balance-sheet damage 68 / 55 is scaled by 0.57 to 38.76 / 31.35; the 3.0 head multiplier (balance sheet issue 6) is provisional. A close headshot deals 116.28 against a round-one Walker's 100 health; a body shot does not kill. Tight ADS, wide hip spread and one strong vertical kick with fast recovery. Talon Reforged doubles damage and reserve, with 22 rounds (+50%, truncated by the existing Tier I rule). Own generated firing crack and tail; shared reload sound.
- **Specimen Vault (provisional rules):** one `SpecimenVault` per map, standing on one of the 6 `vault_spot` markers (starts on the nearest one, the Mess Hall on Halcyon Labs). Needs power, 950 a roll. A roll takes 2.5 s, picks from the map's `pool` (weighted by `WeaponData.crate_weight`, skipping guns the player holds as base or Reforged), then only the buyer can take the gun for 10 s; taking it works like a wall-buy (`WeaponHolder.give`, replaces the gun in hand when both slots are full). After 4 to 8 rolls (`GameSession.rng`) the last roll gives nothing, is refunded, and the Vault jumps to another spot. Halcyon's pool is the AR-7, Brenner Trench, Kestrel SMG and Talon DMR. No rarity or affixes yet (loot phase), no roll animation beyond the label flicking through names, and the navmesh is not rebaked when the Vault moves (one 2 x 1 m box).
- **Power-ups:** `PowerUpData` (`content/power_ups/`) is a name; the effect is one `match` branch in `PowerUp.collect()`. `PowerUpDrops` (in the GameSession) rolls 2.5% per zombie kill with `GameSession.rng`, at most 4 drops a round, types from a shuffled deck. A drop floats 0.8 m above the kill for 25 s, blinks for the last 5 s, and the first living player to touch it collects it for every player. Only Resupply exists (full ammo for every gun of every player; no grenades yet). Blackout rounds and their guaranteed Resupply come later.
- **Exfil:** `ExfilHatch` (`systems/interactables/exfil_hatch.tscn`, Containment Wing floor) opens from round 10 every 5th round, for that round; its frame glows green and the HUD flashes "EXFIL OPEN". A player calls it with the interact key; the 60 s hold counts only while a living player is within 4 m (it pauses, not resets, when nobody is there; provisional). A called exfil stays open past the round end. When the hold finishes, `GameSession.finish_exfil()` adds +50% of the run's XP, freezes the level and shows the results with "Exfil successful". Bonus Scrap and the exfil cache come with loot (P6).
- **Scavenger:** no stat (in `SerumData.EFFECTS`). Each kill by its holder has a 10% chance (`PowerUpDrops.ammo_pack_chance`, provisional) to drop an ammo pack: the `ammo_pack` PowerUpData on the power-up pickup, not in the drop deck and not counted in the 4-a-round cap. Only the player who picks it up gets it: one magazine of reserve for every gun they hold. The "+1 grenade" part waits for grenades.
- **Second Wind (solo):** a Serum with no stat (listed in `SerumData.EFFECTS`; code checks `Player.has_serum()`). Lethal damage with Second Wind puts the player down for 3 s (no input, camera tilts, zombies ignore them because `is_alive()` is false), then back up with full health; Second Wind is used up and the other Serums stay. Its dispenser has `max_sales = 3` and disappears after the third sale. Without it, going down is death and the run ends. Co-op revives come with P7.
- **Sprint stamina:** 4 s of sprint (`Player.sprint_time`, scaled by the `sprint_time` stat). Running out blocks sprint for 3 s, then refills it; stopping early refills over 3 s (provisional). No stamina bar on the HUD.
- **Solo HUD:** anchored mockup layout with round flash/blink, exfil hold box, split ammo and prompt price, Serum code badges and health bar; observes Events and existing read-only presentation state.
- **Tests:** GUT, headless, 94 tests. GitHub Actions runs import, boot test and GUT.
- **Assets:** binaries are in plain git (about 1 MB). No Git LFS for now (decided 2026-11-14); revisit when asset packs arrive, the lines to switch it on are in `.gitattributes`. Up to v0.1 all art is built in code to the style-guide look; packs come after. All sounds are generated by `tools/generate_sfx.py` (original, no licence needed). No third-party assets yet, so `docs/CREDITS.md` is empty.
- **Logging and diagnostics:** `Log` autoload (provisional: not in the architecture doc's autoload list) writes one JSON line per event to `user://logs/run_<time>_<role>_<pid>.jsonl` and a `.summary.json` (rewritten every 30 s, `clean_exit` false after a crash). An engine `Logger` captures `push_error`/`push_warning` and script errors with file, line and stack. `HealthWatch` warns on long frames, low fps, growing orphan nodes and stalled rounds; zombies report being stuck or falling out of the map; the level logs navmesh bake times and warns when navigation is never ready. Keeps the last 20 runs. No desync checks until networking (P7). See `docs/LOGGING.md`.
- **Builds and releases:** see `docs/RELEASING.md`. Exports run on Linux only (Windows cross-exported, no rcedit). Git tag = version. Separate `Build.PROTOCOL_VERSION` and `SaveFile.CURRENT_VERSION`. Godot ignores SIGTERM, so the server quits on a stop file the Docker entrypoint writes. No code signing yet.

- **Debug console and F3 overlay:** debug builds only, children of GameSession; console owns the command registry, authority checks guard tuning commands, and F3 counters refresh at 4 Hz. God mode is deferred until a public damage-immunity API exists.
- **CPU benchmark:** `godot --headless --path . --script res://tools/benchmark/benchmark.gd -- --zombies 24 --seconds 20 --seed 1` (also run 48); skips 2 s warm-up, measures physics callbacks at 60 Hz (no GPU, idle callbacks or standalone server integration), prints mean/P95/P99/max and writes `user://benchmark_<zombies>.json`; PR/manual workflow uploads results without performance thresholds.

- **Headless soak:** normal Halcyon Labs rounds 1–10, seed 1, stationary immortal player; authority hits wait for window entry, JSON-log failures gate the separate optional PR/manual Soak check (see `docs/LOGGING.md`).

## Simplified on purpose (fix before or during the matching build step)

- **Navmesh bakes at load** from the grey-box blocks instead of being baked ahead. Keeps edits safe while the map changes; switch to a baked `.tres` when the layout settles.
- **Zombie AI tiers:** only the re-path interval is tiered. Frame-skipping by tier and off-screen checks come with the performance pass.
- **No Pool autoload yet.** Impacts are capped at 48 and freed; zombies are freed after the corpse fades.
- **Settings autoload** stores controls, video and audio options in `user://settings.cfg`, applies FPS/vsync and bus volumes, and updates `LocalInput` sensitivity and Y inversion. The pause menu opens a three-tab settings screen with immediate saving and reset. Pause/settings use the Cold Containment blue-black panels, teal focus borders, row hints and keyboard prompts from the design references (PR #44). The three-tab layout, Back and reset remain the current scope; the full router, SettingData, font assets/options, search and additional accessibility/comfort pages are deferred. FOV is provisionally horizontal degrees at 16:9 (70–120, default 110, about 78 vertical); PlayerCamera converts it live, while weapon ADS FOV remains vertical. Show FPS uses a tiny HUD label in release builds too, because the F3 overlay is debug-only. Audio / Game autoloads are still deferred; sounds use plain players on the audio buses in `default_bus_layout.tres`.
- **Viewmodel** is a normal mesh close to the camera (near plane 0.03), not the depth-pulling shader. It can poke into walls when you hug them.
- **Procedural animation** for zombies and guns (bob, sway, kick, reload dip). Real clips replace it later.
- **Range falloff** uses start/end distances instead of a Curve.
- **Grey-box art:** boxes with procedural noise materials. First code-built models (wall panel, rifle, Shambler, Crawler, Bloater) exist in `assets/models/` from `tools/assets/build_models.py` and are only placed in the look reference scene so far. Zombie models face +Z with their origin at the feet; each limb is its own node with its origin at the joint (shoulder, hip, neck) so code-driven animation can rotate it. In game, Walker and Runner use the Shambler and the Bloater (`zombie_bloater`, from round 8, no death gas yet) uses the Bloater; `ZombieRig` poses the limbs in code (walk, reach, attack, slack on death) until real clips exist, and the head hit zone is parented to the model's head so headshots follow the animation. The poses run in `_process`, so the head zone's exact spot is a render-loop value; fine for solo, but P7 (server-authoritative hits, rewind) must pose hit zones on the physics tick or use a fixed head anchor. The Crawler is not spawned yet: by design it is made when explosives take a Shambler's legs, and there are no explosives. The player rifle is `rifle_ar.glb`; its bolt kicks on each shot and the magazine drops on reload. Aiming uses a picture-in-picture scope (`ScopeLens`): a second camera renders a 2x view only while aiming, and first-person gun meshes sit on render layer 20 so it skips them.
- **Window barriers (provisional):** 16 window spawn points on Halcyon Labs sit in small spaces behind the walls (`lights: false` rooms in `layout.json`), each with a `Barrier` (6 planks) in the window cut. A zombie spawned there is Entering: it walks to the window, tears a plank every `EnemyData.plank_time` (1.5 s), swipes a player standing at the window, and climbs in once all planks are gone. Players repair one plank per press (0.5 s cooldown) for 10 points, capped at 500 per player per round (`EconomyRules`). Players collide with the Barrier layer, zombies and the navmesh bake do not, so the navmesh runs through windows and only the zombie's state keeps it outside. Not built yet: the AI doc's 3 attack slots and queue points per window (zombies just crowd the window), a sill and a vault animation (the window is a door-height cut; the zombie walks through), hold-to-repair. Plank tear and repair now use generated sounds on scene-owned SFX players. Vents, the ground spawns and the tunnel grate have no barrier.
- **Emergency lighting (provisional):** every `CeilingLight` inside a `Level` with the power off runs at 30% brightness in red-orange with a red tube; on power-on each light switches back within 0.6 s (a ragged wave). No separate emergency fixtures or sound yet; the ambient light and fog stay the same. Lights outside a Level (look reference) are always normal.
