# Prototype decisions

The prototype follows the architecture doc
(https://claude.ai/artifact/XNJ12WAbMJAy2mRNPd5PCx). This file lists what is
built, what was simplified on purpose, and what is still to do.

## Built and matching the doc

- **Ids into data (foundation fix 4, plans/ids-into-data.md):** code no longer picks behaviour by content id. `Content` keeps loaded resources; arm grips are `GripData` files; chain, frost and well come from `WeaponData.effect`; drop chance and rarity floor sit on `EnemyData` (-1 = zombie round curve, which stays as code constants); serum badges on `SerumData`. CI rule `no-content-id-literals` blocks new id literals in `core/` and `systems/`; affixes, rarities, singletons and screens are left out on purpose, and about 20 known leftovers sit in a baseline that may only shrink.
- **UI router (foundation fix 5, plans/ui-router.md):** the `UI` autoload is the only code that changes the scene, stacks screens and sets the mouse mode (CI rule `ui-router-only`). Root places (main menu, match) use `UI.replace`; settings, character, pause and results are pushed screens that emit `closed`; the Pack overlay and debug console use `UI.hold_mouse`. Screen data lives in `content/screens/`, not ui-hud.md's `content/ui/screens/`, because `Content` treats each top folder as one type. Transitions, toasts and layers 40/50 wait until a screen needs them.
- **Item effects in co-op (foundation fix 3, plans/item-effects-server.md):** each owner sends its equipped gear and item guns with `PlayerStateSync.submit_loadout` on spawn and after every Pack equip (trusted client, ADR 0003). The server rebuilds gear stats and `Player.item_guns` from scratch each time; at most 3 gear items, no more guns than weapon slots, and only known gun bases, otherwise `net.loadout_rejected`. Hits carry `DamageInfo.item_uid`; the server keeps it only for a known item gun, bounds the claim with that gun's rolled numbers, and runs `ItemLoadout.apply_hit()` from `Events.enemy_damaged`, so solo, host and clients share one path. Frost shatter pays the item once; collateral and Chain damage add nothing. The Pack overlay only queues an equip; `LootService` runs `ItemLoadout.equip_weapon()` in its physics tick and keeps the run ammo per uid. Not checked: whether a client really owns what it sends (friends-only servers). Traits, set bonuses and showing other players' item guns are later work.
- **Personal zombie loot and Pack banking:** GameSession owns LootService, which rolls only on the server with the session RNG (seed logged as `loot.seed_selected`). Each connected player gets an independent chance using the design source table, round luck (+2% after round 10, capped with gear luck at +100%) and ItemRoller's normalized non-Common luck rule from `loot.csv`. Gear luck comes from the server's copy of each player, filled from the loadout its owner sends (see Item effects in co-op); the server adds round luck. Item level follows the round, capped at 50; base unlocks use the accepted hello level, not run XP or item level. Gear uses `drop_weight`; weapons read metadata `drop_weight`, falling back to the existing `crate_weight × 100` (the roster's scale). Reforged bases stay out; existing weapon rarity floors apply. Prototype rolls select only fixed Prototype bases and carry the reserved Fabricator maximum implicit line without random affixes. Legendary traits and sets still wait for their own batches. Owner-only reliable delivery creates silent local LootDrops: rarity ring/beam, look prompt, F pickup, full-Pack refusal and a 60 s physics Timer. The six-slot Tab overlay uses the shared tooltip, shows carried guns, can equip a Pack gun for this run while retaining its single bankable item and UID-based run ammunition state across replacements, and can discard back to a personal drop. Mouse look stops; movement and the match continue. Pack changes update the count and a four-second feed. At every existing XP-banking exit, Inventory keeps what fits in the local stash before the same profile save; Pack contents survive death and never save on a dedicated server. Results list all items taken and the lost count. `loot.drop_received` records delivery; `loot.stash_item_lost` records each overflow item's uid/base at info level. Supply/exfil caches, gun comparisons in the pickup prompt, trading and extra drop sounds remain outside this slice.

- **Co-op gear looks (trusted client):** each client builds its own `CharacterLook` with `LookBuilder` from its local loadout, after the compatibility hello allows player replication. `LookSync` sends it reliably once when the local player spawns and again only when `GearRig.apply()` changes the encoded look; the server relays it under the sender's peer id, caches it for late joiners, and forgets disconnected peers. Remote copies apply it with `GearRig.apply()`; the owning first-person view keeps its existing shadow-only body and receives no echo application. This replaces the server-built appearance model in `design/gear-visuals.md`: saves live on each client and cosmetics are trusted. The fixed 15-byte payload covers vest, charm and implant, each with a 16-bit visual index, rarity byte and two dye bytes; tables use sorted Content ids checked by C5's content hash. Protocol 2 refuses older builds without the look RPCs before any player spawns. Zero visual means an empty slot, and zero dye selects that channel's default (no dye content exists yet). Unknown indexes, wrong-slot visuals or malformed fields use that slot's base mesh in Common with default dyes; malformed lengths reset all slots. Set counts, crests and effects wait for their own build step.
- **Pack data and results loot column (foundation):** a client-owned plain `Pack` holds six copied item dictionaries and refuses full pickups. Results accept the run's collected items and a stash-overflow count, show rarity-coloured cards with the best first, and state how many were lost. LootService now wires this foundation to private drops, the Pack overlay and Inventory stash banking, as described above.
- **Siphon (fixed Prototype, provisional):** the roster's gravity-well projectile is the one non-hitscan gun. Its provisional 10 m/s orb stops at the first surface or 25 m, then opens a 3 s well capturing at most 12 zombies over its lifetime and pulling only living targets within 6 m. The total per-zombie damage is roster 40 × 0.57 = 22.8 across the full duration, with no range or headshot bonus. The server owns pulls and damage and credits the claiming player; each player has at most two live wells. Recent launch positions keep landing claims valid while the shooter moves, and damage pulses send hit/kill confirmations to the owner. Its fixed `prototype` base has no Reforged variant or random affixes, and enters the Halcyon Labs Specimen Vault pool at weight 0.05; personal Prototype drops now use LootService; Fabricator remains reserved for the ammo system. The code-built Oriel model, viewmodel and generated energy pulse use the existing gun asset pipeline.

- **Equipped item stats (first runtime slice):** `ItemInstance` decodes saved roll fractions against current affix Resources into source-tagged modifiers; `StatBlock` adds increased values, multiplies more factors, adds flat values last and applies the seven limits in `content/loot/stat_caps.tres`. Gear feeds `Player.get_stat()` alongside the existing Serum multipliers, with health, regeneration delay and movement consumers. Gun timing/headshot hooks combine gear and gun buckets; damage, magazine, reserve, pellets, hip spread, range and recoil use independent per-run weapon/recoil copies. Item hits apply flat points and capped leech. Shared Resources and saved dictionaries stay unchanged. Vault and wall-ammo ownership compare stable weapon ids, including Reforged ids, so runtime copies remain recognized.
- **Run loadout bridge (provisional):** the local profile's preserved `loadout` field is a slot-to-item dictionary (`sidearm`, `primary`, `vest`, `charm`, `implant`); absent fields and the old empty-array placeholder keep the scene's starting loadout. The equipped pistol-class Sidearm replaces its start pistol; Vest, Charm and Implant apply to the player. The equipped Primary stays out at spawn: its round-5 Drop Locker is not built. Pack guns are not equipped during this slice. Gear content and Character-screen loadout editing are available; match Pack equipment remains separate work. Traits, sets and `proc` lines retain their save data without running; contextual damage (Close quarters, Long shot, Elite hunter, Executioner) and stagger retain their stat values but have no runtime consumers in the permitted weapon hook yet.
- **Skinned zombies (provisional):** Shambler, Crawler and Bloater use continuous Skin/Subdivision bodies on the shared 22-bone character rig, connected torn coat shells, recessed mouths, detailed blank staff badges and mirrored hands with palm contact. Their dedicated texture-free zombie finish keeps matte skin, restrained cloth wear and a darker veined Belly; heads keep the lightest skin value, and only eyes and Belly glow bio-green. All paint zones remain main; the zombie shader has no dye or rarity inputs. The visual review at `docs/design/reviews/zombies-2026-11-15.md` records fresh before/after renders and hand/pose checks. Counts are 7,700 / 7,248 / 8,776 triangles and 8 / 7 / 8 materials; existing Shambler/Crawler 6,000–8,000 and Bloater 7,000–9,000 ranges stay unchanged (eight materials maximum). Crawler retains every bone but has no mesh weighted to leg bones. ZombieRig drives the procedural poses through bones, with grounded Crawler arm motion and the unchanged head BoneAttachment for the hit zone. Compatibility captures verify shape and value; Forward+ lighting and 24-enemy GPU performance still need validation.
- **Gear finishes and booth (provisional):** one texture-free, object-space `gear.gdshader` covers fabric, webbing, painted plate, polymer, rubber, knit and opaque lens. The character/gear importer selects finishes by Blender material name; AO stays in vertex red and alpha selects glow/trim/accent/main. `GearLook.apply()` sets per-instance dyes and rarity without changing shared materials; six `RarityLook` resources own trim, bounded glow and pulse/flicker. `tools/gear_booth.tscn` renders the player from four angles at 1280×720 under a warm key/rim and AgX; `--out <dir> --rarity all` also writes a sheet with one row per rarity. Its plain model array is the extension point for later gear; effects wait; co-op appearance networking is built above.
- **GearRig and LookBuilder (provisional):** `CharacterLook` holds filled vest/charm/implant visuals, real rarity, default main/accent dyes (`#5F6D68`, `#2F393B`) and set counts across all five equipped slots. Pure `LookBuilder.from_equipped()` maps item `base` and `rar`; unknown bases or visuals use the slot base mesh in Common. An initial base-id mapping covers the three vest frames, five charms and five implants; GearVisual resolves their scenes from content Resources, with medium vest, dog tags and reflex implant as defaults. `GearRig` replaces bone-attached scenes, binds the vest Shell to the body skeleton and removes its first-person cuffs; implant Module and Port follow the left forearm and neck. The body follows synced yaw and its chest and head follow pitch. Third-person clips (F-41) now drive the body through `BodyAnimator`; GearRig still lowers the A-pose arms for previews with no animator (character screen), and `AimPitch` bends chest and head by the synced pitch after the clips. The skinned vest sits in a fixed holder, not a bone attachment, so a posed body moves its skin once. The owner sees only first person while its world body and gear cast shadows only; other players see the body normally. Solo match start reads the CharacterProfile slot-keyed `loadout` dictionary; missing or legacy empty-array loadouts remain empty. Co-op appearance replication is built above; equipped first-person attachments, dyes, crests and effects remain separate steps. `tests/manual/gear_rig_look.tscn` captures the actual player with a Rare vest, Epic charm and Legendary implant in the existing booth; the image needs the person's eye.
- **Teammate animations (F-41, provisional look):** `player.glb` carries code-built clips (idle, four walks, run, crouch idle/walk, downed idle/crawl, fire, reload) from `tools/assets/player_clips.py`. `BodyAnimator` measures each body's movement locally and blends them in an `AnimationTree`, speeding clips up so feet do not slide; `AimPitch` bends chest and head by the synced look pitch. The owner publishes its held gun id and its current reload time (empty mag and Serums included, 0 when not reloading) each tick; PoseSync sends them with crouch. Each peer puts `WeaponData.world_model` (the bare gun `.glb`) in `hand_R`, with the grip point on the palm. Fire and reload are upper-body one-shots: fire plays from the relayed remote shot, reload is stretched to that synced reload time and fades out when the reload ends. Simplified: one two-handed rifle pose for every gun (pistols included), one reload clip for every gun and reload kind (empty and per-round reloads only change its speed), and the remote muzzle flash still plays at the owner's first-person muzzle. A dedicated server poses nothing.
- **Vest frames (provisional):** light is a flat chest rig, medium adds compact clavicle pads, and heavy adds broad pads and a tall collar. Each exports one Shell on the shared 22-bone rig, rigidly weighted world cuffs/pads, two unskinned first-person cuffs and a spine-mounted CharmClip. Source and exported geometry clear the full undersuit by at least 3 mm at rest. The task's light 3,000–4,500, medium 4,000–5,500 and heavy 4,500–6,000 triangle ranges replace the design document's provisional 3,000-triangle vest target. Four Gear finish names share the alpha-zone shader; trim covers at least 5%, glow at most 5% and only emits from Rare up. The booth shows the medium at six rarities or all three frames on the player body; GearRig now applies equipped swaps on the gameplay body.
- **Character and gear build tools (provisional):** shared 22-bone A-pose rig, deterministic segment weights and rigid binding; character/gear checks enforce budgets, registered stems, rig/weight rules and attachment origins. `Color` RGB keeps baked AO; alpha encodes main 1.0, accent 0.667, trim 0.333 and glow 0.0, with glow capped at 5% of surface area. The character registry includes the base player body, first-person arms and three vest frames; other gear meshes come in later batches.
- **Base player body (provisional):** `characters/player.glb` is a 1.80 m Lantern Post salvager undersuit on the shared 22-bone rig. One continuous Skin/Subdivision mesh carries the thermal suit and knitted balaclava, with carved seam channels; patches, goggles, gloves, boots and belt add sewn and rigid details. BodySuit, BodyKnit, BodyRubber and BodyLens select the four body finishes through the shared gear import. The character review raises the body cap to 16,000 triangles (quality increase authorized 2026-11-15), funding local elbow/knee support edges and smoother shared glove palms; the 8,000 detail floor and four-material limit remain. Inward folds preserve the fitted torso/cuff envelope, with committed vest clearance checked. Broad-shouldered proportions, cold-weather tailoring and goggle tint are provisional; first-person arms and vest frames are separate builds described above and below.
- **First-person arms (provisional):** `characters/player_arms.glb` keeps all 22 body bones and their rest transforms, with weights only on arm bones. Sleeves share the body's folded surface and fitted cuff envelope; BodySuit, BodyRubber and BodyKnit retain its paint zones. The authorized character review raises the cap to 10,000 triangles, retaining the 5,000 floor and three materials. One `PlayerArmView` per local weapon holder replaces the placeholder hands, with camera-relative shoulders and grips following existing weapon motion. Authored profiles cover each weapon family and its upgraded variants; glove morphs preserve the approved rifle Basis and unchanged triangle count. Fitted gloves bind rigidly to hand bones to prevent reload clipping, while sleeves and cuffs keep flexible weights. Pose-specific wrist fabric corrections retain the shared rest shape; two stock grips also move the shoulders during the existing sprint blend. Generated fingertip metadata ships beside the GLB; markers retain names and parents. The default rifle keeps its original clearance checks and 32 mm right / 45 mm left tip gaps; other profiles use actual fingertip positions, allowing natural thumb lengths on wide stocks. The rig and bone-attached medium cuffs use viewmodel layer 20 and no cast shadows, so scopes exclude them. Common cuffs are cosmetic, with no equipment state. Remote players and dedicated servers do not instantiate the rig. Fingers remain fixed curls; trigger pulls and magazine-handling clips are deferred.
- **Skill tree data and spending rules:** the 20 named design nodes load through Content, with provisional rows/columns and no prerequisite links specified yet. SkillTree checks free points, rank limits, prerequisites and branch gates without changing input ranks or content. No stat effects or Trainer screen yet; town respec limits and Scrap costs wait. Only the named nodes exist, so the 15/25-point gates cannot be reached until more nodes are added as data (normal ranks total 14 Marksman, 10 Survivor and 13 Tinkerer).
- **Weapon loot roller (first affix batch):** AffixData/AffixTier and RarityData Resources hold 22 weapon lines, three rarity-based implicit ammo lines and six rarity tables. ItemRoller uses only the supplied RNG for rarity/luck, counts, tag/family exclusions, gated tiers, roll fractions and ids, returning the versioned plain item dict; Legendary rolls four lines with a null trait, and Prototype weapon rolls are rejected. Equal-fifth tiers use a 0.1 step where their boundaries are fractional (otherwise 1). Traits, named Legendaries, sets, match drops and loot UI wait for later batches.
- **Gear loot and visual data (provisional names and base tuning):** 13 GearBaseData resources link the three vest frames, five charms and five implants to GearVisual scenes; their attachment bones are `spine_02`, `spine_03` (chest clip) and `forearm_L`. Lantern Post names are Lantern Rig, Salvager Vest, Cordon Shell, Tether Tags, Oriel Vial, Halcyon Pass, Kessel Meter, Post Token, Ridge Reflex, Ridge Lung, Salvager Spine, Oriel Eye and Pell Relay; resource names flag them as provisional. All bases start unlocked at level 1 with equal drop weight 100 and their slot as a loot tag until drop balance is built. The 24 gear affixes use the same seeded item dict and rarity/count/family/tier rules as weapons, with `imp: null`; fixed Skill rank and Extra grenade stay +1 and require Rare plus item level 15/22. Their five standard tiers keep equal values. Regen delay uses a provisional 0.01-second step instead of the design example’s 0.1 seconds to preserve the equal 0.14-second tier boundaries. `Inventory.slot_for()` resolves gear from GearBaseData alongside the existing explicit Primary/Sidearm weapon slots, so normal stash equip and unequip operations also accept rolled gear. Shared gun and sprint lines target the existing runtime stat keys, and ItemInstance decodes the positive regen-delay roll as a negative flat modifier so its displayed reduction shortens the delay. Remaining stat effects, named skills on the Skill rank line, traits, sets, drops and inventory UI remain later work.
- **Character inventory:** each profile saves 60 stash slots (`{}` for empty) and five loadout entries: primary, sidearm, vest, charm and implant. Inventory has static add/remove/equip/unequip operations; equipping swaps back into the source stash slot and unequipping refuses a full stash without changes. Save version stays 1: missing inventory fields and legacy empty loadout arrays default to empty slots while preserving XP, and unknown item fields survive unchanged. Newly stored item copies receive an optional acquired order; equipment moves preserve it for newest sorting. WeaponData has an explicit Primary/Sidearm slot, including on Reforged variants; gear slot lookup uses GearBaseData. Inventory operations have no match calls or UI; the existing run-loadout bridge consumes equipped items separately.
- **Godot 4.7.2, Forward+, Jolt at 60 Hz, physics interpolation on.**
- **Typed GDScript enforced:** `untyped_declaration` and `inferred_declaration` are errors (addons excluded).
- **Folders:** `core/` autoloads, `systems/<feature>/` code + scenes, `content/<type>/` data only.
- **Autoloads:** `Events` (past-tense facts only), `Content` (id = file name, strips `.remap`, keeps each loaded resource until `reload()`, `has(type, id)`), `Net` (`is_authority()`, id allocation).
- **Round scaling (plan `docs/plans/core-loop-gaps.md`, step 1):** `WaveRules` follows the design: counts 6/8/13/18 then floor(0.09r² + 0.6r + 15); round health 120 + 90 per round to round 9, then x1.09, applied as a multiplier on each `EnemyData.max_health` (the round-one health, so the Walker stays 100 at round 1 until F-07 tunes it); spawn delay 2.0 s x0.95 per round, min 0.3 s; co-op count x(1 + 0.5 per extra player) and max alive +6 per extra player; no damage growth. Speed-mix enemies (`EnemyData.uses_speed_mix`, the Walker) roll Shamble/Jog/Run/Sprint (1.2/2.6/4.2/5.6 m/s) from `SpeedBand` rows with `GameSession.rng`; the separate Runner type is gone. Numbers match `balance/rounds.csv` (unit test).
- **Content as Resources:** `WeaponData` + `RecoilData` (per-shot pattern), `EnemyData`, `WaveRules` + `EnemySpawnEntry`, `EconomyRules`. Live state is in `WeaponInstance`; `.tres` files are never mutated (tested).
- **Damage:** `DamageInfo` (amount, attacker, weapon id, type, zone, position, normal, impulse) → `HitZone` (Area3D on layer 4) → `HealthComponent`. Weapon head/limb multipliers from data, per-zone armour on the HitZone.
- **Collision layers 1-8** named as in the doc.
- **Multiplayer rules:**
  1. Player reads `InputFrame`s from a `LocalInput` node, never the keyboard.
  2. Damage, spawns, XP only apply where `Net.is_authority()`.
  3. Logic emits facts; muzzle flash, sound, impacts and hit markers react (weapon `fired`/`traced` signals).
  4. Gameplay in `_physics_process`; `GameSession.tick` counts ticks. Weapon `tick()` runs from the player's physics step; `_process` is visuals only.
  5. All enemies come from `Spawner`, which assigns `net_id`.
  6. Gameplay randomness uses `GameSession.rng` (seedable).
  7. XP goes through `ProgressionService` (one in-memory class for now).
  8. No global player: everything loops the `players` group.
- **Local character (P5):** one `solo` character until character selection in P6. `user://characters/<id>.json` stores id, display name, total XP and skill ranks (empty until skills); level comes from total XP. Unknown fields survive saves. Game over, exfil (after +50%) and leaving early bank run XP once; unreadable/newer files stay untouched and use a temporary character.
- **Economy:** per-player `Wallet`; `Economy` pays from `EconomyRules` and owns `try_spend()`.
- **XP rules and levels:** `XpRules` (`content/progression/xp_rules.tres`) holds kill/round rewards and the rounded level curve from the balance CSV. `ProgressionService` owns run XP plus a starting total from the local character, grants headshot and living-player round-clear XP, and emits every new level up to 50. Skill-point totals include the five bonus levels (54 at level 50); skills are not built yet. Exfil still bonuses only run XP.
- **Wave director:** intermission → `round_started` → spawning (max alive cap, extra per player) → clearing → `round_ended`.
- **Zombie AI:** enum state machine (Spawning, Entering, Chasing, Attacking, Dead), NavigationAgent3D with avoidance off plus cheap separation, re-path interval by distance (0.25 / 0.5 / 1.5 s), target = nearest living player every 0.5 s.
- **Fire timing:** time accumulator plus a 0.12 s input buffer, semi / burst / auto.
- **Look:** volumetric fog, depth fog, AgX, SSAO, glow, flickering shadowed lamps, moonlight, player flashlight.
- **Look reference (Cold Containment):** `levels/look_reference/halcyon_corridor.tscn` rebuilds the style guide's Halcyon Labs corridor in Godot. Its `WorldEnvironment` points at the shared `levels/looks/halcyon_interior.tres`; interior game scenes must use this file, not a copy. Render it with `tools/look_shot.gd` (command in the file). Differences from the guide's table, on purpose: AgX instead of ACES; ambient energy 0.2 instead of 0.35 (baked bounce now fills the shadows); fog albedo is a light teal-grey because Godot's fog albedo is the scatter colour (the guide's #0A1416 was the web renderer's fog colour). Grain and vignette come from `systems/effects/film_post.tscn` (a CanvasLayer any scene can add). Zombies there are the code-built Shambler, Crawler and Bloater models (static, no game logic), and no light flickers so renders stay comparable. Style-guide light budget: at most 6 shadowed real-time lights in view (tested). Surface detail is procedural and world-space, no texture files: `levels/materials/grime.gdshader` (wall drips, floor-level dirt, ceiling stains; the wall panel's glTF materials are remapped to it in its `.import` file) and `wet_tiles.gdshader` (tiles, grout, mirror puddles for SSR). Fixtures have a dark housing; one unshadowed `ZombieRim` spot behind the zombies shines back toward the player so silhouettes read. Bounce light is baked with LightmapGI (High, 3 bounces, denoiser, texel scale 2; about 2.3 MB in `halcyon_corridor.exr` + `.lmbake`, plain git). Fixtures and the bio-leak glow use bake mode Dynamic: direct light and shadows stay real-time, only their bounce is baked. `ZombieRim` and the camera `ViewFill` are cheat lights with bake mode Disabled. Each fixture has a `CeilingGlow` omni (bake mode Static, no shadow, no fog) just under it, so the ceiling between fixtures gets the spill a real tube gives; it exists only in the bake and costs nothing at run time. Zombies and the rifle import with light baking Dynamic, so they are not baked and take light from the lightmap probes. The wall panel imports with Static Lightmaps (UV2, `.unwrap_cache` committed so UV2 is the same on every machine). `Block` builds its box at runtime as an internal child, which LightmapGI skips (it ignores unowned nodes), so `Block` hands the box over through `get_bake_meshes()` / `get_bake_mesh_instance()`, the hooks GridMap uses. **Re-bake after any geometry or light change:** Godot 4 has no command-line bake, so open the scene in the editor on a GPU, select `LightmapGI`, press Bake Lightmaps, save, and commit the new `.exr` and `.lmbake`.
- **Halcyon Labs (default map, blockout):** `levels/halcyon_labs/layout.json` holds rooms (rect, floor height, ceiling height), door cuts and ramps as plain data. `tools/blockout_builder.gd` turns it into `blockout.tscn` (command in the file; never hand-edit the output, a test fails if it is stale). Walls are runs of the code-built wall panel with one collision box per run; ceiling lights are the kit scene `levels/kit/ceiling_light.tscn`, two shadowed per room. `map.tscn` holds the gameplay nodes: player spawn, 21 `ZombieSpawnPoint`s (each tagged with its area), dock props, orange doors and green machine placeholders. `Level.open_area()` puts an area's spawn points into the Spawner's group; only the Loading Dock is open at the start. Closed doorways cut the navmesh (tested). Layout and costs follow the maps doc (https://claude.ai/artifact/UxyrXQqFfonMxh3MgFMYWY). The prototype courtyard is removed.
- **Halcyon Labs lightmaps:** the full map is baked with LightmapGI like the corridor (High, 3 bounces, denoiser), texel scale 1.5 instead of 2 so the files stay small for plain git: about 13 MB (`map.exr` 12.8 MB + `map.lmbake` 0.2 MB). The `LightmapGI` lives in `map.tscn`, not in the generated `blockout.tscn`; the builder now gives the wall strips above the panels UV2 so they bake. Baked: blockout floors, walls, ceilings, ramps, kit panels, dock props, Med Dispensers, Reforger, power switch, exfil hatch. Not baked, because they move or vanish and would leave their shadow in the lightmap: door blockers, wall-buy boards and the Specimen Vault body (`Block.baked = false`, lit by the probes), barrier planks (GI Dynamic), the vault glow (GI Disabled). In-game zombies set their meshes to GI Disabled at spawn: their limbs move every frame and Dynamic GI re-sampled the probes for each limb each frame, which cost about a quarter of the frame with 24 zombies (the corridor's static zombies keep the Dynamic import). Every `CeilingLight` Fixture is bake mode Dynamic; the Spill omni lights are deleted from the kit (the bake now gives that fill, and rooms keep more contrast). Power-off: the bounce is baked with the power-on colours, but it is faint enough that the emergency rooms still read dark red (screenshots matched before and after), so LightmapGI energy and the 0.2 ambient stay as they are. Window spawn spaces stay dark. At 1440p with 24 zombies the four test spots run 400 to 500 fps, the same as before the bake. **Re-bake after a layout change:** rebuild the blockout (`tools/blockout_builder.gd`), open `levels/halcyon_labs/map.tscn` in the editor on a GPU, select `LightmapGI`, press Bake Lightmaps, and commit only `map.exr`, `map.exr.import`, `map.lmbake` and `map.tscn` (revert anything else the editor re-saved, and keep `map.tscn` free of editor-only uids). A layout change that removes baked meshes breaks the map's tests until the re-bake (LightmapGI errors on missing nodes); run `tools/prune_lightmap_users.gd` to drop those entries and keep the rest of the bake. Ramp ends get no sill in their opening (the sill top was a lip that stopped zombies at the top of the Containment ramp).
- **Signal in the Static (Halcyon Labs secret, provisional):** three `WallRadio`s (Guard Post, Generator Hall, Labs) under one `RadioPuzzle` in `map.tscn`. At power-on the server hands out the three tones (pitch 0.75 / 1.0 / 1.3) in a random order from `GameSession.rng`; each radio hums its tone every 8 s until lit. Landings under 3 m/s are silent, then the thud goes from -14 dB to full at 10 m/s and drops in pitch. Floors built from the `rust` or `pipe` materials sound metal (the list is on the scene), everything else concrete. Four generated variations per surface (`tools/assets/footstep_sfx.py`) through an `AudioStreamRandomizer` (±6% pitch, ±1.5 dB). Zombie footsteps, the Foley bus and SoundManager pooling wait for the sound foundation step.

Area3D boxes over those rooms (no physics monitoring) are checked against the current camera four times a second, so the bed follows the local player or the teammate being spectated, with a 1.5 s crossfade. One key, one action across all actions: a taken key offers Swap or Cancel, and per-action reset uses the same swap rule. - **Co-op, steps 1-3 of 6 (provisional, see `docs/MULTIPLAYER.md`):** trusted client (the person's choice, 2026-11-15): each PC moves its own player and claims its own hits; the server owns shared state. `Net.host/join/leave` with `--host` and `--join=addr:port` on the command line; `PlayerSpawner` gives each peer a `Player` named after its peer id (also its `net_id`), owned by that peer; `PoseSync` sends position, yaw and head pitch.
